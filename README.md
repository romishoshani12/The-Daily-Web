# The Daily Web

אתר חדשות בעברית עם סביבת עבודה לכתבים ולעורכים.

## טכנולוגיות

HTML5, CSS עם Flexbox ו־Media Queries, JavaScript רגיל, Fetch/Ajax, Node.js, Express, EJS, MongoDB ו־Mongoose. הגרף מצויר ב־Canvas. הצפנת סיסמאות משתמשת ב־scrypt מתוך `node:crypto`. אין React, Vue, Angular, Bootstrap או ספריית ממשק חיצונית. שלוש התלויות היחידות של האפליקציה הן Express, EJS ו־Mongoose, המופיעות בדרישות.

## התחלה מהירה — בדיקת העיצוב בלי מסד נתונים

נדרשת התקנת Node.js 22 ומעלה. פתחו טרמינל בתיקיית האתר:

```bash
npm ci
npm run preview
```

פתחו `http://localhost:3001`. התצוגה מסומנת כ״תצוגת עיצוב בלבד״ ומציגה פיד, כתבה, סביבת כתב, דסק עורך, סטטיסטיקות ומשתמשים. חיפוש, סינון ודפדוף זמינים לצורך סקירה; התחברות, כתיבה ושמירה אינן פעילות במצב הזה. אין צורך להזין סיסמה. גרסת התצוגה אינה חלק מהשרת האמיתי ואינה עוקפת הרשאות שלו.

## הרצת המערכת המלאה

1. התקינו Node.js 22+ ו־MongoDB Community מקומי והפעילו את שירות MongoDB.
2. הריצו `npm ci` בתיקיית האתר.
3. העתיקו את `.env.example` לקובץ חדש בשם `.env` באותה תיקייה. ב־PowerShell אפשר להריץ `Copy-Item .env.example .env`; ב־macOS/Linux: `cp .env.example .env`.
4. הגדירו `MONGODB_URI=mongodb://127.0.0.1:27017/daily_web` או כתובת של מסד משלכם.
5. צרו סוד אקראי באמצעות הפקודה הבאה, והעתיקו אותו לשדה `SESSION_SECRET` בקובץ `.env`:

```bash
node -e "console.log(require('node:crypto').randomBytes(32).toString('hex'))"
```

6. בחרו סיסמת הדגמה בת 10 תווים לפחות והגדירו אותה ב־`SEED_PASSWORD`. אין סיסמאות אמיתיות או מפתחות במאגר.
7. במסד חדש וריק בלבד, הריצו:

```bash
npm run seed
npm start
```

8. פתחו `http://localhost:3000`.

ל־seed יש הגנה מפני דריסת משתמשים או כתבות קיימים. הוא לא מוחק את מסד הנתונים. אם רוצים הדגמה חדשה, הגדירו שם חדש למסד ואל תמחקו עבודה קיימת.

| שם משתמש | שם | תפקיד |
|---|---|---|
| `romi` | רומי | כתבת |
| `nofar` | נופר | כתבת |
| `bar` | בר | כתב/ת |
| `roy` | רועי | כתב |
| `ben` | בן | עורך |

הסיסמה לנתוני ההדגמה היא הערך שבחרתם ב־`SEED_PASSWORD`. התפקידים בנתוני הדוגמה אינם חלוקת משימות הפיתוח. מומלץ להסיר את `SEED_PASSWORD` מהקובץ לאחר ההזנה. שמרו על אותו `SESSION_SECRET` בין הפעלות כדי לאפשר המשך שימוש עם העוגיות הקיימות.

## מה המערכת כוללת

- פיד של גרסאות מאושרות בלבד, טעינה של 20 בכל בקשה, גלילה אינסופית, חיפוש כותרת, קטגוריה, נצפה/לא נצפה ומיון לפי זמן או צפיות.
- עמוד כתבה עם התוכן המלא ב־HTML שמוחזר מהשרת, קישור לשיתוף ותגובות ללא רענון. כותבים טקסט רגיל, והוא מוצג escaped כדי למנוע הזרקת HTML.
- התחברות, sessions ב־MongoDB, הרשאות בשרת, סיסמאות עם salt ו־scrypt, הגנת CSRF והגבלת ניסיונות התחברות.
- סביבת כתב, שמירה אוטומטית לשרת, הערות תיקון והגשה מחדש.
- עותק `draft` נפרד מ־`published`; הציבור ממשיך לראות את העותק המאושר בזמן תיקונים, בהמתנה ולאחר החזרה לכתב.
- דסק עורך: חיפוש וסינון, עריכה, אישור, החזרה עם הערה, השוואה לגרסה המאושרת ומחיקת כתבות.
- ניהול משתמשים: יצירה, חיפוש, עריכת שם/תפקיד/סיסמה, השבתה ומחיקה. משתמש שיש לו כתבות מושבת במקום להימחק, כדי לשמור על שיוך הכתבות.
- ניהול תגובות לעורך דרך עמוד הכתבה: עריכה ומחיקה.
- גרף צפיות שעתי עם סימוני פרסום גרסאות, בחירת כתבה וחלון זמן, טבלת נתונים נגישה וכלי תיקון/הוספה/מחיקה של רשומות צפייה.
- ווידג׳ט Open-Meteo ללא מפתח API או כרטיס אשראי. השרת משתף בקשה אחת בין בקשות מקבילות ומציג שגיאת זמינות במקום נתונים ישנים מדי.
- סקריפט ל־600 כתבות: 510 בעלות גרסה ציבורית, מתוכן 30 בתהליך עדכון, ועוד 90 כתבות שלא פורסמו. חמישה משתמשים, 80 תגובות ו־6,720 רשומות צפייה שעתיות. 15 כתבות כוללות כמה אירועי פרסום.

## מבנה האתר

```text
app.js / server.js       הגדרת Express, אבטחה והרצת השרת
config/                  קטגוריות וסטטוסים
models/                  מודלי Mongoose ואינדקסים
routes/                  נתיבים לפי אזור אחריות
controllers/             פעולות HTTP
services/                לוגיקת פרסום, ולידציה, הצפנה, צפיות ומזג אוויר
middleware/              זיהוי המשתמש, CSRF ובדיקת תפקיד
views/                   תבניות EJS ו־partials
public/css/              עיצוב בסיס ועיצוב לפי פיצ׳ר
public/js/               JavaScript בדפדפן לפי פיצ׳ר
public/images/           איורי SVG מקוריים מקומיים
scripts/seed.js          הזנת נתוני הדגמה למסד ריק
scripts/preview.js       תצוגת עיצוב נפרדת, ללא מסד
scripts/check.js         בדיקת תחביר ורינדור תבניות
scripts/setup-check.js   בדיקת קונפיגורציה וחיבור למסד
 tests/                  בדיקות לוגיקה ובדיקות אינטגרציה
 docs/                   דרישות, חלוקת עבודה, חוזי API ומדריך הגנה
```

## בדיקות

```bash
npm test
npm run check
npm run doctor
```

`npm test` מפעיל בדיקות לוגיקה. בדיקת האינטגרציה מסומנת כ־SKIP עד שמגדירים MongoDB לבדיקה. `npm run check` בודק תחביר, מודלים ותבניות ללא MongoDB; `npm run doctor` בודק את ההגדרות והחיבור למסד בלי לכתוב בו.

כדי להפעיל בדיקות מקצה לקצה, הפעילו MongoDB והגדירו בטרמינל:

PowerShell:

```powershell
$env:TEST_MONGODB_URI="mongodb://127.0.0.1:27017"
npm test
```

macOS/Linux:

```bash
TEST_MONGODB_URI=mongodb://127.0.0.1:27017 npm test
```

הבדיקה יוצרת מסד עם שם אקראי `daily_web_test_*`, מפעילה שרת HTTP אמיתי, עוצרת ומפעילה מחדש את תהליך השרת, ובסיום מוחקת רק את המסד שהיא יצרה. אין להריץ עם חשבון שאסור לו ליצור מסד בדיקה. ההרצה כוללת הרשאות, שמירה, הגשה/החזרה/אישור, אי־חשיפת טיוטה, HTML ראשוני, שלוש תגובות בדקה בבקשות מקבילות, 600 כתבות, CRUD ו־restart.

פירוט מצב הבדיקות בפועל: `docs/verification.md`. תסריט ידני להגנה: `docs/defense.md`.

## מגבלות שחשוב להבין

- בדיקות הקבלה מול MongoDB אמיתי עברו. בדיקת עומס של אלפי משתמשים לא בוצעה; אין לייחס לבדיקות הקבלה הוכחת קיבולת כזו.
- כל שינוי נשלח אוטומטית לשרת. חיווי ״נשמר״ מעיד על אישור מהשרת; עבודה שנשמרה זמינה במחשב אחר. בזמן ניתוק רשת מוצגת שגיאה והדפדפן מבקש לא לעזוב עם שינויים שלא נשמרו. אי אפשר להבטיח שמירת הקלדה שטרם הגיעה לשרת במקרה של כיבוי כפוי או אובדן חיבור.
- ״אותו מכשיר״ והיסטוריית נצפה מזוהים באמצעות עוגייה חתומה של הדפדפן. ניקוי עוגיות או שימוש בפרופיל אחר יוצר זהות חדשה; זו אינה זיהוי חומרה בלתי ניתן לעקיפה. ההיסטוריה מוגבלת ל־10,000 מזהי כתבות כדי להימנע ממסמך שגדל ללא גבול.
- לכל שעה יש רשומת צפייה אחת לכתבה, עם הגדלה אטומית. סך הצפיות בכתבה הוא מונה נוסף; העדכון שלו ושל הרשומה השעתית אינו transaction משותף. קריסה בדיוק ביניהם יכולה לחייב התאמת מונים. אין כאן התחייבות לקיבולת שנמדדה באלפי משתמשים.
- מטמון מזג האוויר הוא לכל תהליך Node. זוהי תצורה של שרת יחיד; הגדלה למספר מופעים דורשת מטמון משותף. זמן המדידה שנמסר מהספק נבדק בנוסף לזמן השליפה.
- נתוני ההדגמה ואיורי ה־SVG מקוריים ונועדו להדגמה; הכתבות אינן חדשות אמיתיות.
- שימוש חיצוני ב־HTTPS מחייב `NODE_ENV=production`; בהרצה מקומית על HTTP יש להשאיר `development`. אין להפעיל את `scripts/preview.js` כשרת המערכת האמיתי.

## עבודה בצוות

חלוקת העבודה מתוארת ב־`docs/team-plan.md`, חוזי ה־API ב־`docs/contracts.md` ומפת הדרישות ב־`docs/requirements.md`. העבודה התבצעה בקומיטים קטנים ובענפים לפי פיצ׳רים, שנכנסו ל־main דרך pull requests.

כל אחד עובד מחשבונו ועל המחשב שלו. כל חברי הצוות מכירים גם את האזורים שאינם בבעלותם.

## הבחנה בין המערכת המלאה לתצוגת העיצוב

להתחברות, שמירה, תגובות ואישור כתבות השתמשו ב־`npm start` עם MongoDB. `npm run preview` מציג רק עמודי קוראים לצורך סקירת עיצוב. אין בו משתמשי צוות מדומים או החלפת משתמש לפי כתובת; גישה לאזור צוות מפנה למסך הכניסה עם הסבר.
